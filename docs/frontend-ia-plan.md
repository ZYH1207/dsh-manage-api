# dsh-manage-api 前端功能排布（IA）重排方案

> 目标：让插件更"用户友好"、更贴合 DSH —— 而不是继续在现有 9 个 tab 里加功能。
> 依据：① 现有代码（逐条给 `文件:行号`）；② DSH 官方 Web 客户端的槽位契约与同类页面范式（`resources/app.asar` 内官方包 README + 客户端 bundle 实测）。
> 本文只谈**排布**（信息架构、导航层级、入口位置、状态反馈），不涉及视觉皮肤；视觉层问题另见 `docs/frontend-review.md`。

## 一、功能清单：现在到底有哪些东西、分别挂在哪

### 1.1 面板之外的四个挂载点（插件在 DSH 里不是"一个页面"，而是"四个面 + 两个非 UI 面"）

| 挂载点 | 注册位置 | 用户看到什么 |
|---|---|---|
| 主面板 `main`（key `manage-api`） | `lib/client.js:6955` | 全窗口工作台，9 个 tab |
| 侧栏图标 `sidebar.panellist`（id `manage-api`, order 40） | `lib/client.js:6956-6966` | 左栏一个图标，点开上面的主面板 |
| 设置分区 `settings.section`（id `manage-api`, order 60） | `lib/client.js:6967-6977` | 设置弹窗左侧导航多一项「ManageAPI」，内容是**同一个** 9-tab 工作台 |
| 会话成本 `conversation.chat.assistant-actions`（id `manage-api-cost`, order 30） | `lib/client.js:6978` | 每条助手消息下的花费 chip |
| 模型工具 ×3 | `lib/tools.js` | `manageapi_status` / `manageapi_models` / `manageapi_usage` |
| 命令 `/manage` | `lib/commands.js` | `status/models/usage/budget` 四个子命令 |

关键结论：**同一个 9-tab 工作台被同时挂到"主面板"和"设置分区"两处**（`ManageShell` 两种 `variant`，`lib/client.js:6771`）。DSH 里主面板是"工作区页面"（如「自动化任务」「Plugins」），设置是"模态偏好面板"——两者承载的东西不该一样。

现有 9 个 tab 是一层平铺（`TABS`，`lib/client.js:322-332`），但业务上分属四个域：

### 1.2 主面板 9 个视图，按业务域归类

| 业务域 | 现有视图 | 视图里实际装了什么 |
|---|---|---|
| **A 概览** | overview（`src/parts/05-overview.js`） | 最划算头条、4 张 KPI、需要关注（问题站点）、自动 DSH 选模型、站点速览表 |
| **B 供给侧** | monitor（`10-monitor.js`，1432 行） | 真实花费 KPI、余额概览 SVG、告警、站点表、新增站点（内联表单 `:844`）、账单同步 |
| | free（`20-free.js`） | 免费池站点/模型、可用性探测 |
| | gateway（`30-gateway.js`） | 网关入口地址、最近请求日志 |
| | probes（`70-probes.js`） | 探针任务、运行结果、健康点 |
| **C 模型侧** | pricing（`50-pricing.js`） | 比价表、忽略模型弹窗、改价输入（禁用） |

### 1.3 写操作共 12 项，散落在 7 个视图里

写白名单共 **18 条**（`lib/write-proxy.js:25-44`，默认拒绝）。其中「识别系别」（`:30`）、「账号登录」（`:33`）**前端没有任何入口**；前端实际接线的写动作 19 个（含同一规则多处触发）。下表按「用户任务」归并成 12 项。

| 写操作 | 现在在哪 | 可达性 |
|---|---|---|
| 新增站点 | monitor 页内向导 | ✅ |
| 编辑/删除站点 | monitor 行内 | ✅ |
| 增删/轮换网关 Key | monitor 的 Keys 区 | ✅（但网关页也有 Key 概念，两处并存） |
| 忽略模型 | pricing 弹窗 | ✅ |
| 改价 | pricing 行内输入 | ❌ 禁用（白名单已放行，UI 没接，`50-pricing.js:4-5`、`:99`） |
| 决策排序 | decision | ❌ 禁用 |
| 运行探针 | probes | ✅ |
| 同步账单/模型 | monitor | ✅ |
| 告警已读 | monitor 告警卡 | ❌ 未接 |
| 网关开关 | gateway | ❌ 锁定 |
| 自动 DSH 接入模型 | overview 卡片 | ✅ |
| 用量区间 7/90 天 | usage | ❌ 禁用 |

**没有任何一个页面是"管理/设置"归属地**：管理动作分散在只读看板里，用户要改东西得先猜它在哪页。

### 1.4 关键任务的入口深度（现状）

| 任务 | 路径 | 层数 |
|---|---|---|
| 加一个站点 | 设置 → ManageAPI → 站点 → 新增站点 → 向导 | 4 |
| 改价 | 设置 → ManageAPI → 比价 → 找到行 → 改输入框（禁用） | 4+（且走不通） |
| 忽略模型 | 设置 → ManageAPI → 比价 → 忽略模型 → 弹窗 | 5 |
| 看今日花费 | 概览 KPI / 站点页 / 用量页 —— **三处口径不同**，要自己判断看哪个 | 2~3（不确定） |
| 跑探针 | 设置 → ManageAPI → 探针 → 运行 | 3 |
| 接入 DSH | 设置 → ManageAPI → 概览 → 滚到底 → 自动 DSH 卡 | 4 |

## 二、现状问题（IA 视角）

按"影响使用"从大到小排序。每条给现象、证据、为什么是问题。

### IA-1（P0）9 个 tab 平铺，没有分组，也没有"当前在哪"的层级感
- 现象：`overview / monitor / free / pricing / decision / probes / gateway / usage / benchmark` 全部同级（`lib/client.js:322-332`）；其中 pricing 与 decision、monitor 与 free/gateway/probes 强相关，却被拆成并列项。
- 证据：TABS 定义与 `ma-tabs` 渲染 `lib/client.js:6891-6913`。
- 为什么是问题：用户要找"花费"必须遍历 9 个词；每个 tab 都有两行文案（title + desc），导航本身就是首屏最大的一块；tab 之间没有父子关系，无法表达"站点下面有 Key / 账单 / 探针"这种结构。

### IA-2（P0）设置模态里塞了一整个工作台
- 现象：`settings.section` 注册的是 `PanelSection` → `ManageShell variant="section"`（`lib/client.js:6967-6977`、`:6924`）。
- 证据：DSH 的设置是**模态面板**：外壳渲染"模态面板 + 由 `settings.section` 条目构建的导航 + 一次只挂载一个分区"（官方 `dsh-client-ui-settings-general` README「使用本包」）。模态宽度有限，里面放 9 tab + 表格 + SVG 图表必然挤压。
- 为什么是问题：工作台（看数据、长时间停留）和偏好设置（改开关、一次性操作）是两种使用节奏；DSH 其它插件的分区都是"摘要 + 表单"（如 `dsh-client-ui-settings-shell` 的 `SettingsForm`：`label/hint/overridden/save/discard`），没有一个分区塞 9 个看板页。

### IA-3（P1）页面有两层导航，DSH 页面惯例只有一层
- 现象：壳顶栏（`h2` 标题 + 副标题 + 状态 pill + 刷新 + 自动刷新区，`lib/client.js:6857-6888`）下面紧跟 `ma-tabs` 两行按钮（`lib/client.js:6891-6913`）。
- 证据：DSH 页面骨架是单行 `pageHeading`（官方 schedule 页面 bundle 实测：`display:flex;flex-wrap:wrap;justify-content:space-between;gap:16px;margin-bottom:24px;padding-top:28px`，标题 `font-size:20px;font-weight:500;line-height:28px`，右侧动作 `white-space:nowrap`）。
- 为什么是问题：首屏被两层导航吃掉约 1/5 高度；tab 里的 desc 与副标题重复表达同一件事（副标题还随 tab 改写，`lib/client.js:6825-6829`）。

### IA-4（P0）没有"详情层"，页面只能越来越胖
- 现象：monitor 1432 行同时承载 真实花费 KPI + 余额概览图 + 告警 + 站点列表 + 新增向导 + 同步；站点和模型都只有"表格行"，没有详情页。
- 证据：`src/parts/10-monitor.js` 行数；`05-overview.js:275-294` 站点只是一个表格行。
- 证据（DSH 范式）：官方「自动化任务」页 = **列表页（搜索 + 一行状态筛选）→ 选中进入第二层详情（详情内有 tab：规则 / 运行记录）→ 详情顶部条带的"更多操作"菜单放删除**（`dsh-client-ui-schedule` README「使用本包」）。列表行只放"标题 + 状态 + 频率 + 下次运行"四要素。
- 为什么是问题：站点/模型是天然实体（1 个站点下有 Key、账单、探针、模型；1 个模型下有多个站点供给），把它们压扁成表格行，只能把所有细节塞回列表页。

### IA-5（P1）同一信息在多处重复，口径还不一致
- 现象："花费"出现在 概览 KPI、站点页 KPI、用量页；"告警"出现在 概览"需要关注"与站点页告警卡；"模型"出现在 概览（头条/站点速览）、比价、决策、基准价 四处。
- 证据：`05-overview.js:38-63`（KPI）、`10-monitor.js` 真实花费区、`80-usage.js` 趋势；概览的"站点速览"与 monitor 的站点表是两份不同列的表。
- 为什么是问题：同一指标三处呈现，用户会怀疑"哪个才是真的"；代码上则是三份重复的取数/格式化逻辑，改口径要改三处。

### IA-6（P1）写操作藏在只读页面里，且禁用后没有出路
- 现象：**3 处「白名单已开、UI 仍灰置、title 还谎称未开放」**：改价（`src/parts/50-pricing.js:4-5`、`:99` vs 白名单 `lib/write-proxy.js:43`）、决策排序（`src/parts/60-decision.js:7`、`:44`）、刷新汇率（`src/parts/40-benchmark.js:206` vs `:46`）。此外网关开关 `gatewayLocked`、用量 7/90 天禁用且 title 说「没有 `/api/usage` 路由」（`src/parts/80-usage.js:5`、`:245-246`）。
- 为什么是问题：禁用理由与真实能力不一致（改价其实能写），而且禁用按钮既没告诉用户"为什么不行"，也没给"那我能做什么"；用户会认为插件坏了。

### IA-7（P1）加载 / 空 / 失败三种状态混为一谈
- 现象：`state=null`（加载中）时概览直接渲染"从添加一个中转站开始"引导（`05-overview.js:166-188`）；全文件 `skeleton` 0 处、`aria-` 仅 3 种。
- 为什么是问题：首屏会闪一下"你没有站点"，数据回来又跳走；失败时也没有"重试"按钮（`useApi` 的 `.then` 无 `.catch`）。

### IA-8（P1）页面之间没有链接，跳转靠"切 tab"，插件自己都承认了
- 现象：概览"全部站点 →"只是 `onGoTab('monitor')`（`src/parts/05-overview.js:285`）；用量空态"去配置网关"按钮被**禁用**，title 写着「插件面板不支持跨页跳转，请用左侧「网关」页」（`src/parts/80-usage.js:226`）。
- 证据（DSH 能力）：`ctx.layout.selectPanel(id)` 可跨面板选中（官方 `dsh-client-ui-layout` README）；面板间还可通过共享客户端状态传参（待补充：宿主是否有正式的"面板参数"契约，当前按模块级 store 设计）。
- 为什么是问题：诊断类任务永远是"看到异常 → 去对应实体 → 处理"，没有深链接就只能手动找；而插件已经为此把按钮做成禁用的了。

### IA-8b（P2）同一个功能有两份实现，其中一份是死代码
- 现象：旧版 `SitesTab` / `KeysTab` / `SiteWizard`（`lib/client.js:625`、`:724`、`:912`）仍在内联基座里并通过 `__internals` 导出（`:7016`），但 `TABS` 与 `viewMap` 都不引用；真正可用的「新增站点」是 `10-monitor.js:844` 的内联表单。
- 为什么是问题：两套「加站点 / 管 Key」代码同时存在，改一处忘另一处就会行为分叉；死代码还会误导后续接手者（本次审计中就一度把它当成现行功能）。

### IA-9（P2）顶栏把"全局工具"和"页面动作"混在一起
- 现象：状态 pill、探针健康点、刷新、自动刷新都在顶栏（`lib/client.js:6861-6888`），而"新增站点""运行探针"这类页面主操作却散在页面内部。
- 为什么是问题：DSH 页面规范是"标题左、页面主操作右"（schedule 页头的「新建」）；全局状态属于侧栏/状态区，不属于每个页面。

### IA-10（P2）tab 用"两行按钮"承载说明文案
- 现象：每个 tab 渲染 `nav-title` + `nav-desc` 两行（`lib/client.js:6891-6913`）。
- 为什么是问题：9 个两行按钮约 2 行高 × 9，横向还得滚动（`.ma-tabs{overflow-x:auto}`）；说明文案应该属于页面副标题，而不是导航。

## 三、DSH 的界面契约：排布必须遵守什么

这些是从官方包 README 与客户端 bundle 里实测的，直接决定"怎么排才像 DSH"。

1. **主面板与侧栏图标是一对**：插件在 `sidebar.panellist` 注册 `{id, order, label}`，`id` 必须等于 `main` 的 key；选中不存在的 key 会抛错（`dsh-client-ui-sidebar` README）。导航行间距 2px；收起态用 tooltip 显示 label。
2. **跨页面跳转用 `ctx.layout.selectPanel(id)`**（`dsh-client-ui-layout` README）；`null` 表示回到会话界面。
3. **应用级提示走 `shell.overlay`**：官方 schedule 的删除结果「任务已删除 / 无法删除任务」写在应用级 overlay 里，所以提示的生命周期长于发起它的面板/页签（`dsh-client-ui-schedule` README）。
4. **设置是模态 + 左侧 section 导航**：`settings.section` 是"分区页"，不是卡片；分区内可以用 `settings.plugins.tab` 注册页内标签行（`dsh-client-ui-settings-plugins` README）；官方插件配置页的标准形态是"一行摘要 + SettingsForm 表单（字段带 label/hint/已覆盖标记/保存/取消）"（`dsh-client-ui-settings-shell` client bundle 实测）。
5. **实体型页面 = 列表 + 详情两层**（schedule 范式）：列表页有搜索框 + 一行状态筛选，行只放 4 个要素；点行进详情；详情内 tab；删除放"更多操作"；脏草稿只在有改动时出现"保存栏"（`有未保存的修改 / 取消 / 保存修改`），保存失败保留草稿并给本地化提示；空态保留页头主操作；加载/空/失败三态区分，失败保留旧数据 + 重试。
6. **页面骨架尺寸**（schedule bundle 实测）：页面根 `height:100%;display:flex;overflow:hidden;background:var(--dsw-alias-bg-base);color:var(--dsw-alias-label-primary);font-size:14px;line-height:1.6`；内容 `max-width:960px`；页头 `padding-top:28px` + `var(--dsh-frame-top-clearance)`（macOS 红绿灯/Windows 标题栏预留）；标题 `20px/500/28px`。
7. **列表行用纵向 gap 10px 的卡片列表**，而不是密排表格（`.list{flex-direction:column;gap:10px}`）。

> 结论：DSH 的"管理型页面"范式是 **列表 → 详情 → 操作**，不是"9 个看板 tab"。

## 四、重排方案

### 4.1 四条原则

1. **一个域一个一级入口**：一级导航 = 用户脑子里的业务域（概览/供给/模型/消费），不是数据表。
2. **列表进、详情出**：站点、模型都必须有详情层；列表页只保留"能比较、能筛选"的 4-6 个字段。
3. **写操作跟着实体走**：改站点在站点详情，改模型在模型详情，改全局偏好进设置；看板页只读。
4. **一个指标只有一个家**：完整视图唯一，其它页面只放"摘要 + 链接"，且标注口径。

### 4.2 目标信息架构

```
ManageAPI 工作台（main panel, 侧栏图标 1 个）
├─ 概览            ← A 域
│   ├─ 最划算头条 / 4 KPI（站点、供给、可比较模型、最大价差）
│   ├─ 需要关注（唯一告警归属；点条目 → 站点详情）
│   └─ 快捷入口（新增站点、接入 DSH、查看账单）
├─ 供给            ← B 域（3 个子页）
│   ├─ 站点（列表 → 站点详情）
│   │    列表列：名称 / 状态 / 余额 / 今日花费 / 可用模型 / 健康
│   │    详情：概览(余额+账单曲线) · 模型供给 · Key · 同步与探测 · 危险操作
│   ├─ 免费池（免费模型/站点、可用性）
│   └─ 网关与探针（网关入口+最近请求 | 探针任务与结果）
├─ 模型            ← C 域（3 个子页）
│   ├─ 比价（列表 → 模型详情：各站价格/可用率/探针结果；行内改价、忽略）
│   ├─ 决策（路由顺序 + 推荐；行内排序）
│   └─ 基准价（参考表，只读）
├─ 用量            ← D 域
│   ├─ 花费趋势（7/30/90 切换）
│   └─ 预算（本月额度/已用/预警；只读 + 跳设置改额度）
└─ 设置（settings.section，不再是工作台）
    ├─ 连接（daemon 端口/自动启动/父进程守护）
    ├─ 刷新（轮询间隔/自动刷新默认开关）
    ├─ 预算（sessionTokens/dailyTokens）
    ├─ 自动 DSH（provider 名/是否显示卡片/当前接入模型只读显示）
    └─ 写权限与危险操作（白名单一览、重启 daemon、导出配置）
```

一级从 9 → 4，二级每组 ≤3，最深 3 层（域 → 子页 → 详情）。

### 4.3 旧 → 新映射

| 现视图 | 去向 | 说明 |
|---|---|---|
| overview | **概览**（精简） | 保留 头条/KPI/需要关注；"自动 DSH"卡移入设置分区，概览只留一行"当前接入模型 + 管理"链接 |
| monitor | **供给 › 站点**（列表）+ **站点详情**（余额/账单/告警/同步） | 新增站点改为列表页头主操作；余额概览与告警进详情 |
| free | **供给 › 免费池** | 独立子页（数据源与站点不同，不适合塞进站点列表） |
| gateway | **供给 › 网关与探针** | 网关入口 + 请求日志；探针并入同页第二个 tab |
| probes | **供给 › 网关与探针**（探针 tab） | 探针是"供给可用性验证"，与网关同域 |
| pricing | **模型 › 比价** | 忽略模型入口放列表页头"筛选"位；改价进模型详情行内 |
| decision | **模型 › 决策** | 排序在详情；列表显示当前顺序 + 推荐理由 |
| benchmark | **模型 › 基准价** | 只读参考表，放最后一个子页 |
| usage | **用量 › 花费趋势** | 区间切换接通；预算独立子页 |
| settings.section（整个工作台） | **设置分区（仅偏好）** | 9-tab 工作台从设置里移除，改成 5 组偏好 + "打开工作台"按钮（`ctx.layout.selectPanel('manage-api')`） |

### 4.4 三个关键流程重设计

**（1）加一个站点**（4 层 → 2 层）
```
供给 › 站点（列表页头右侧「新增站点」）→ 弹窗/详情式向导（3 步：站点信息 → Key → 拉模型）
```
- 向导从"页内表单"改为"详情式向导"（DSH 范式：点开进入第二层，有明确的取消/完成）。
- 完成后落回列表并高亮新行 + `shell.overlay` 提示「站点已添加」。

**（2）改价 / 忽略模型**（分散 → 归位）
- 比价列表：行内只显示价格 + "改"图标；点行进**模型详情**，在"各站报价"表里行内编辑，失焦保存，脏值显示保存条。
- 忽略模型：列表页头「筛选 › 管理忽略」打开弹窗（现状保留），但入口从行内按钮改成页头，避免每行一个按钮。

**（3）看花费**（三处 → 一处完整 + 两处摘要）
- 完整视图唯一：**用量 › 花费趋势**（日/周/月，站点账单口径 actual，标注"读不到账单"而非估算）。
- 概览 KPI 只显示"今日花费"并链接到趋势页；站点详情只显示"本站今日/本月花费"，标注口径。
- 告警唯一归属：概览"需要关注"；站点详情显示该站告警摘要。

**（4）接入 DSH**（藏在概览底部 → 设置里可预期）
- 设置分区「自动 DSH」：provider 名、是否在主面板显示卡片、当前接入模型（只读 + "更换"按钮弹模型选择）。
- 概览保留一行"已接入：deepseek-v4.1-flash › 管理"，点击跳设置分区。

### 4.5 页面骨架规范（落地时统一）

| 元素 | 规范 | 现状 |
|---|---|---|
| 页头 | 单行：`h1` 20/500/28 + 右侧动作（`gap:16px`, 动作 nowrap）+ 副标题一行 13px | 双层导航 + 两行 tab |
| 页头内边距 | `padding-top: 28px + var(--dsh-frame-top-clearance,0px)` | 无 |
| 内容宽度 | `max-width: 960px` 居中（主面板）；设置分区不限宽 | 1120px |
| 一级导航 | 侧栏图标（1 个）+ 主面板内**分段控件**（segmented/下划线 tab，单行、无 desc） | 9 个两行按钮 + 横向滚动 |
| 二级 tab | 仅"供给""模型"两组可切换子页，样式与 DSH 分区 tab 一致 | 无 |
| 列表 | 卡片式列表，行间距 10px；行 = 名称 + 状态 + 2-3 个关键数值 + 右侧 chevron | 密排表格 |
| 详情 | 独立视图（非弹窗），顶部返回 + 标题 + 更多操作菜单 | 无 |
| 状态 | 加载=骨架行；空=空态 + 页头主操作；失败=保留旧数据 + 重试条 | 加载=空态；失败无处理 |
| 保存 | 脏才出现保存条（`有未保存的修改 / 取消 / 保存修改`），失败保留草稿 | 行内直接写，无保存条 |
| 结果反馈 | `shell.overlay` 应用级提示（成功/失败） | 行内 ok-line，短命 |

### 4.6 设置分区职责收敛（`settings.section`）

只保留"改了就影响全局、平时不看"的东西，形态对齐官方插件配置页（摘要行 + 表单）：

1. **连接**：daemon 端口、自动启动、父进程守护（`--parent-watch`）、当前状态只读。
2. **刷新**：默认轮询间隔（15s/30s/60s/关）、进面板是否自动开自动刷新。
3. **预算**：`sessionTokens` / `dailyTokens`（0=不设限，文案说明超限会拒绝请求）。
4. **自动 DSH**：provider 名（默认 `manage-api`）、是否显示卡片、当前接入模型只读 + 更换。
5. **写权限**：白名单一览（只读表格，来自 `lib/write-proxy.js` 的 `WRITE_RULES`）+ "写操作被拒时的提示文案"说明。
6. **危险操作**：重启 daemon、导出配置、清空本地缓存（二次确认）。

页面顶部一个主按钮「打开工作台」→ `ctx.layout.selectPanel('manage-api')`。

## 五、收益与风险

### 收益
| 维度 | 现状 | 重排后 |
|---|---|---|
| 一级入口数 | 9 | 4 |
| 加站点 | 4 层 | 2 层 |
| 改价 | 走不通 | 模型详情 2 层内完成 |
| 花费口径 | 3 处、口径不一 | 1 处完整 + 2 处摘要（标注） |
| 首屏导航占用 | 顶栏 + 两行 tab | 单行页头 |
| 状态语义 | 加载=空 | 三态区分 + 重试 |
| 与 DSH 的一致性 | 自造壳 | 复用 pageHeading / 列表→详情 / overlay / 设置表单 |

### 风险
1. **习惯迁移**：老用户记住的是"比价在 pricing tab"，重排要一次性改导航。缓解：首版保留旧 tab 顺序作为页内分段控件的默认顺序（供/模型两组），并在文档写清映射。
2. **跨面板参数**：概览 → 站点详情的深链接需要"面板参数"（待补充：宿主是否提供正式契约；当前按客户端模块级 store 实现，刷新后回落到列表页）。
3. **移植成本**：9 个视图要拆成"列表页 + 详情页 + 设置表单"约 14 个组件，`src/parts/*` 需要重组；建议按 P0/P1 分批。
4. **设置分区职责变化**：从设置里拿掉工作台后，只从设置进入的用户会"找不到看板"。缓解：设置分区顶部「打开工作台」+ 概览空态引导。
5. **写操作接通**：改价/排序/7-90 天/告警已读需要接白名单与 UI，属于功能接线，不是纯排布；建议与重排解耦，单独排期。

## 六、落地建议（分三期，每期可独立验收）

### P0 结构骨架（1-2 天）——先让"导航与页头"像 DSH
1. `lib/client.js` 壳：顶栏改单行 pageHeading（标题 20/500/28 + 副标题 13px + 右侧全局工具收进"更多"菜单）；`padding-top` 接入 `--dsh-frame-top-clearance`；内容宽 960。
2. `TABS` 改为两级：一级 4 项（概览/供给/模型/用量），二级仅供给（站点/免费池/网关与探针）与模型（比价/决策/基准价）。
3. 一级导航改单行分段控件，去掉 desc；tab 状态进 URL hash（`#/supply/sites`）以便深链接与刷新保持。
4. `settings.section` 换成"偏好页"骨架（5 组 + 打开工作台按钮），工作台从设置移除。
5. 删除死代码 `SitesTab` / `KeysTab` / `SiteWizard`（`lib/client.js:625`、`:724`、`:912`、`:7016`），避免与新列表/详情页并存。
- 验收：从侧栏进面板 2 层内到达任一旧页面；设置分区只剩偏好；`scripts/check.mjs` 全绿；首屏无两层导航。

### P1 列表→详情（2-3 天）——站点与模型实体化
1. 站点列表页 + 站点详情（余额/账单/Key/同步/告警摘要）；新增站点改列表页头主操作 + 详情式向导。
2. 模型比价列表 + 模型详情（各站报价、改价行内、忽略管理入口上移页头）。
3. 加载/空/失败三态 + 重试；保存条 + `shell.overlay` 结果提示。
4. 概览去重：KPI 保留 4 个 + 需要关注 + 快捷入口；"自动 DSH"精简为一行链接。
- 验收：加站点 2 层；改价走通；概览不再重复站点表；空态不再误报。

### P2 精修（1-2 天）——一致性收尾
1. 剩余写操作接线（决策排序、7/90 天、告警已读、网关开关按用户决定是否开放）。
2. 空态插画/骨架屏、键盘可达性（tab 方向键、Home/End、focus-visible）、`aria` 补齐。
3. 文档：`docs/frontend-ia-plan.md`（本文）+ README 的入口说明更新。

> 说明：本文按用户要求**只出方案，不改代码**。P0 的壳与导航改动集中在 `lib/client.js` 与新增 `src/parts/` 导航文件，风险可控；P1/P2 会改动 `src/parts/*` 的组件边界，建议每期单独提交、单独重载验证。
